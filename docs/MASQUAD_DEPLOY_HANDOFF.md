# Промпт для подготовки MASQUAD / Giovanna к публикации и CI/CD

Ты работаешь как инженер, отвечающий за выпуск существующего сайта. Нужно изучить текущий проект, подготовить приватный репозиторий и настроить безопасный, воспроизводимый CI/CD на сервер пользователя. Сначала проверь фактическое состояние файлов и инфраструктуры: этот документ описывает состояние на 14 ноября 2026 года и не заменяет чтение кода.

Не создавай новый сайт, не заменяй дизайн шаблоном и не переписывай проект на фреймворк ради деплоя. Сохрани существующие взаимодействия, мобильную вёрстку, прямые ссылки, историю браузера и поддержку reduced motion. Не публикуй сайт и не переключай DNS без явно установленного назначения сервера и разрешения владельца.

## 1. Что это за продукт

MASQUAD — сайт команды разработки. Главная представляет собой интерактивный пиксельный космос с планетой Giovanna. На планете расположены четыре проекта: WearningLords, Scandere, GoPhoto и сама Giovanna. Сайт — одновременно портфолио, демонстрация интерфейсной инженерии и точка входа в обсуждение разработки.

Ранее бренд назывался ESSCALE. Видимые надписи и метаданные заменены на MASQUAD. Технические имена `Esscale`, ключи `esscale-orbit`, `esscale-arrival`, тип сообщения `esscale-page`, существующие URL `esscale.ru` и Telegram `sborka_esscale` сохранены намеренно. Не заменяй их вслепую: это рабочие идентификаторы и реальные внешние адреса. Новый домен, Telegram и юридические данные нужно получить у владельца.

Проект находится в `D:\work`. Папка `D:\fortz` содержит материалы для передачи контекста, а не обязательно исходники сайта. Не спутай сайт с другим проектом Scandere или документом его CI/CD.

## 2. Стек и характер архитектуры

- Статический многостраничный сайт: HTML, CSS, обычный JavaScript. Для работы сайта не нужны Node-сервер, база данных, авторизация, API или сборка.
- Node используется для генератора и тестов. В корне на момент проверки нет `package.json`, lockfile, готового workflow или конфигурации веб-сервера.
- Главная и солнечная система: программная растеризация на низкоразрешённом Canvas 2D с пиксельным масштабированием. Это живой мир с изменением координат камеры, а не уменьшение скриншота.
- GoPhoto: собственные WebGL-шейдеры, 50 000 точек, переход между надписью и сферой; при отсутствии WebGL — Canvas 2D примерно на 8 334 точки.
- Three.js и внешнего 3D-движка нет. Эффекты объёма карточек реализованы CSS transforms и JavaScript.
- CSS/WAAPI, requestAnimationFrame, Pointer Events, IntersectionObserver, ResizeObserver, matchMedia используются для анимаций и интерактива.
- В `js/vendor/gsap/` могут лежать старые библиотеки. Их наличие не означает, что текущий сайт использует GSAP. Проверяй реальные подключения HTML.
- Локальный кириллический шрифт `assets/fonts/OrbitPixel.ttf`, SVG-иконки и рамки. Основные страницы не должны зависеть от CDN.
- Состояние орбиты/возврата — sessionStorage; исследованные проекты — localStorage. Персональные данные на сервер не отправляются. Telegram-ссылка формирует черновик сообщения, отправляет его сам посетитель.

## 3. Страницы и сценарии

### Главная: `index.html`

Планета вращается сама и вручную. Маяки получают случайные, достаточно разнесённые позиции при новом входе; при возврате сохраняется раскладка. Стрелки и клавиатура переключают все четыре проекта. Маяк открывает мини-карточку с описанием, функциями, стилизованным превью и кнопкой перехода. Есть список проектов и прямые ссылки.

Открытие карточки приостанавливает вращение. Наклон карточки следует за курсором с инерцией. Переход на проект проходит через облака; возврат выполняет обратный полёт. Есть отмена, пропуск и сокращённое движение при prefers-reduced-motion.

В космосе есть спутники, созвездия, метеориты и необязательные открытия. Удержание планеты/кнопка запускают сканирование. Спутник может подсветить Giovanna. После реального посещения проект отмечается исследованным; после всех четырёх есть однократная надпись из звёзд.

Кнопка «Как устроена Giovanna» запускает отдельный полёт: отдаление по дуге, солнечная система с восемью планетами, разная глубина объектов, освещение от Солнца, возвращение к выбранному маяку и облака. Стартовый импульс маяка и заголовок внутри облаков по просьбе владельца УДАЛЕНЫ — не возвращать.

### Направления и калькулятор

`pages/directions.html` описывает услуги и контакт. `pages/calculator.html` содержит расчёт. Они также открываются поверх главной через диалог с iframe. `js/page-overlay.js` и `css/page-overlay.css` отвечают за этот сценарий, `?panel=...`, Back/Forward и обмен сообщениями. Сами страницы должны оставаться доступны напрямую. Проверь работу по HTTP, поскольку первоначально многое проверялось через file://.

Не запрещай собственные iframe заголовком `X-Frame-Options: DENY` или CSP `frame-ancestors 'none'`: это сломает текущий интерфейс. Для этого сайта допустим same-origin подход. Проверь `event.source`, `event.origin`, целевой origin postMessage и допустимые значения сообщений; сейчас есть отправка на `'*'` и проверка источника окна. При усилении защиты учитывай локальный режим file://.

Калькулятор: 8 серверных работ, 5 мобильных, 3 коэффициента; коэффициенты перемножаются и применяются только к серверной части. EP округляются до двух знаков, недели вверх. Текущие параметры: 3 500–5 000 рублей/EP, 15 EP/неделю. Не изменять бизнес-формулу без владельца. Проверить актуальность ставок перед публикацией.

### WearningLords

Светлый зелёный лендинг изучения слов: интерактивная тренировка, проверка ответа с допуском частичных ответов/опечаток, переворот карточки на 180° после успешного ответа, рамка из 190 частиц, топики, демонстрационный график, правило трёх дней и выбор языка. ### GoPhoto

Сейчас это плагин Lightroom Classic, а не старый концепт фотосервиса. Только две основные сцены: сборка надписи GoPhoto из 50 000 бирюзовых точек; ниже инструкция слева и сфера справа с волной от точки касания. Указаны версия 0.2.3 и Lightroom Classic 12+. В текущей странице нет скачивания архива/запроса доступа — это известный контентный пробел, нужны реальные материалы владельца.

### Scandere

Тёмная страница «Мир по имени Giovanna», мини-планета и четыре описательных блока. Фоновые контурные линии удалены после жалобы на нагрузку. Не включать их обратно. Файл `giovanna-field.js` теперь содержит только движение блоков; название историческое.

## 5. Известный долг и ограничения

- CSS нарастал слоями; есть общие глобальные селекторы и дубли облаков. Giovanna подключает `gophoto.css` ради общих правил. Не удалять «лишние» подключения без проверки.
- Глобальный объект `Esscale` и порядок defer-скриптов значимы. Не менять загрузку на async без рефакторинга зависимостей.
- `app.js` совмещает рендер, состояние и UI. Некоторые исходники очень плотно отформатированы.
- Есть постоянно работающие анимационные циклы, не везде остановка вне viewport. На WearningLords перехватывается колесо; на GoPhoto возможна GPU-нагрузка, особенно с Canvas fallback. Тяжёлый контурный фон уже удалён.
- Обработчик resize главной отменяет открытые сценарии; проверить изменение viewport мобильной адресной строкой.
- Мелкая пиксельная типографика и небольшие кнопки требуют проверки читаемости, масштаба 200% и клавиатурного фокуса. Не заявлять соответствие WCAG без отдельной проверки.
- В аудите 5 ноября обнаруживался выход блока WearningLords на ~3 px при ширине 390 px. Проверь, остался ли он; с того времени файлы менялись.
- Мало настоящих экранов и результатов проектов; сильные маркетинговые обещания требуют проверки. Не выдумывать цифры, отзывы, скачивания и ссылки.
- Нет подтверждённой готовности SEO, OG-изображений, sitemap, canonical, редиректов и серверного кэширования. Настраивать под реальный домен, не выдуманный.
- README местами устарел: встречаются шесть страниц вместо семи, старые длительности полёта и ссылки на отсутствующий `temppublic`. Актуальные файлы важнее описания.
- Локальные замеры CPU не доказывают FPS на мобильных устройствах, безопасность и показатели опубликованного сайта. Нужны HTTP/staging и реальные устройства.

## 8. Требуемая схема CI/CD

1. Pull request: проверка путей, синтаксиса, расчёта, геометрии и взаимодействий. Ошибка тестов блокирует выпуск. Автоматизировать браузерные тесты; сейчас они ожидают CDP 9222, некоторые используют локальные file://. Не выдавать наличие тестов за готовую CI-систему.
2. Push/merge в согласованную основную ветку: собрать allowlist-артефакт сайта — `index.html`, `pages/`, `css/`, нужные `js/`, `assets/`. Исключить `.git`, artifacts, профили браузера, секреты, docs, tests и временные файлы из публичной раздачи. Добавить идентификатор коммита/релиза.
3. Деплой только из доверенных событий, без передачи production-секретов в PR из форков. Production Environment/секреты, минимальные permissions, последовательные деплои с concurrency. Зафиксировать версии зависимостей CI и при необходимости Actions по SHA.
4. SSH отдельным пользователем с минимальными правами. Проверенный known_hosts/fingerprint; не отключать проверку ключа хоста. Приватный ключ — в хранилище CI, не в репозитории. Предпочесть доставку готового артефакта серверу, чтобы production не требовал широкого GitHub-токена.
5. Атомарные релизы: `releases/<commit>/`, проверка загрузки/полноты, затем переключение `current`. Не синхронизировать с удалением в живую папку или корень сервера. Сохранить несколько предыдущих релизов и команду отката.
6. До переключения проверить конфигурацию веб-сервера, после — HTTP smoke test главной, CSS/JS, шрифта, семи страниц и iframe. При провале восстановить предыдущий релиз. Для атомарности учесть посетителей со старым HTML: нужны версионированные ассеты или совместимый переход между релизами.
7. HTTPS, HTTP→HTTPS, сжатие, MIME-типы. HTML с revalidation; долгий immutable cache только для версионированных/хешированных ресурсов. Сейчас имена CSS/JS постоянные — не ставить им годовой immutable без изменения схемы версий.
8. Сайт многостраничный: не подменять все неизвестные URL главной как для SPA. Настоящие 404, корректные `pages/*.html`, относительные пути. Если заменяется старый домен — согласованные 301 для прежних адресов, не blanket redirect всего на главную.
9. Защитные заголовки совместить с собственными iframe и WebGL. CSP сначала проверить: используются динамические style/innerHTML, Canvas, inline SVG/атрибуты. Не включать строгую политику вслепую. Не отправлять секреты в клиент.
10. Документация: как выпустить, проверить, откатить, обновить секреты; какие данные у владельца ещё не подтверждены. Не выдавать созданный workflow за работающий CI/CD, пока не прошёл реальный запуск и production-проверка.

Браузерные проверки: `browser.test.js`, `project-navigation-browser.test.js`, `solar-browser.test.js`, `discoveries-browser.test.js`, `card-browser.test.js`, `learning-browser.test.js`, `gophoto-browser.test.js`, `giovanna-field-browser.test.js`. HTTP-проверки важны: file:// не проверяет заголовки, кэш, CSP и раздачу сервера. Проверить также низкую высоту/landscape, касание, Tab/Escape, Back/Forward, прямые URL, новое окно, reduced motion, WebGL fallback, повторное посещение и возврат через облака.
